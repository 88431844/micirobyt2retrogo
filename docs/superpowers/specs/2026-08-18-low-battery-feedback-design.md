# Low-Battery Feedback Design

## Goal

让 MicroByte 用户分别配置系统运行时 LED、低电量 LED、低电量声音和低电量屏幕处理，同时保留低电保护的存档与休眠能力。

本阶段采用轻量方案：声音使用固件生成的短提示音，不加入语音或 WAV 资源；屏幕提示使用现有 GUI 对话框；所有配置保存到全局设置。

## User Experience

### LED 设置

在 `选项 -> LED 选项` 中提供：

- `系统活动`：关闭、负载闪烁、常亮、呼吸灯、慢闪烁、快闪烁、双脉冲。
- `低电量`：关闭、常亮、呼吸灯、慢闪烁、快闪烁、双脉冲。
- `磁盘活动`：保留现有开关。

默认值保持当前行为：系统活动使用随负载变化的短脉冲，低电量使用慢速闪烁。低电量状态优先级高于系统活动；低电量模式关闭时，LED 恢复显示系统活动。

MicroByte 的 GPIO2 是单色 LED。呼吸灯使用 GPIO2 的 LEDC PWM；如果目标没有可用 PWM，退化为分级亮灭，不影响其他目标编译。低电量 LED 模式只控制这颗状态灯，不改变 LCD 背光或充电电路。

### 声音设置

在 LED/电源提示子菜单中提供 `低电量声音`：

- `关闭`
- `进入低电量时提示一次`
- `低电量期间重复提示`

提示音为短双音（约 120ms），不使用语音合成；重复模式默认每 30 秒最多提示一次。进入临界电量时额外播放一次更紧急的双脉冲提示。音量跟随系统音量，系统静音或无可用音频设备时自动静默。

### 屏幕提示

采用两级策略：

1. 电量首次降至 15% 以下：显示一次短暂的“电量低”消息，不打断游戏输入。
2. 电量降至 3% 以下：显示模态对话框，提供“忽略”和“存档并关机”。

选择“存档并关机”时，先调用当前应用的 `saveState`，再进入现有 `rg_system_sleep()` 流程。选择“忽略”时继续运行，并在电量恢复到 8% 以上前每 60 秒最多重新提示一次；这样用户可以继续游戏，但不会永久关闭保护。进入充电/恢复阈值后清除本轮提示状态。

## Architecture

### LED pattern engine

新增独立的 LED 模式枚举和纯函数，根据模式、当前时间和系统负载计算 LED 亮度（0-255）。系统监控任务每 100ms 调用渲染函数：

- 系统活动模式使用系统负载作为 `负载闪烁` 的周期输入。
- 低电量模式覆盖系统活动模式。
- 临界保护对话框期间保持低电量模式，不在后台线程直接操作 GUI。

设置使用全局键 `LedSystemPattern`、`LedLowPattern`、`LowBatterySound`。读取时对未知值回退到默认值，写入时使用整数枚举，避免语言变化影响配置。

### Battery state machine

沿用现有电压校准、16 点平均和迟滞阈值：低电量进入/恢复为 15%/20%，临界进入/恢复为 3%/8%。在系统监控任务中只更新状态和待处理事件；所有 GUI、存档和休眠动作在主线程 `rg_system_tick()` 中执行。

事件只在状态边沿触发，避免每秒重复播放声音或重复弹窗。设备重启、拔电或恢复到恢复阈值时清除边沿锁存。

### Audio

在 `rg_audio` 增加短音调播放接口，使用固定大小的立体声 PCM 缓冲分块提交到当前音频驱动。接口对 dummy sink 和未初始化音频安全返回，不改变游戏音频 API。音调生成使用整数相位累加，避免在系统监控任务中分配大块内存。

## Persistence and Compatibility

- 新设置缺失时使用默认值，旧配置无需迁移。
- `LED 选项` 现有磁盘活动开关保持兼容。
- 目标未定义 LED 或 PWM 时隐藏不可用的 LED 菜单项，并保留低电状态逻辑。
- 低电保护不依赖声音或 LED；即使用户关闭提示，临界存档/休眠仍可用。

## Testing

- 主机纯函数测试：六种 LED 模式的亮度/周期、负载闪烁边界、低电状态边沿去重。
- 设置测试：缺省值、非法枚举回退、旧 LED 开关兼容。
- 本地化测试：新增菜单、提示和对话框全部进入翻译目录。
- MicroByte 构建检查：ESP-IDF 编译、LEDC 通道与 LCD 背光通道不冲突。
- 实机验收：逐项切换 LED 模式；验证 15% 单次提示、3% 对话框、忽略重试、存档后休眠。

## Non-Goals

- 本阶段不加入“Battery low”语音文件或用户自定义音频上传。
- 不改变电池 ADC 引脚、电压校准流程或充电检测硬件。
- 不把低电提示扩展成完整的通知中心。
